perf(android): fast-core threads, token-budget splitting, warm G2P

Adopted the parts of Marmalade TTS's speed design that fit sherpa-onnx:

- CpuClusterDetector.java: choose intra-op threads from cpufreq clusters
  (skip the efficiency tier, drop a lone prime core when >=2 fast cores
  remain, fallback (nProc+1)/2, clamp 1..8). KokoroPlugin's default uses it.
- JS now treats an unset thread setting as auto (sends no count), so the
  detector actually applies; the panel gains "Auto (fast cores)" and shows
  the loaded session's count.
- splitForModelByTokens: split native Kokoro sentences by real phoneme
  tokens (480 budget under the 510 window) using ONE G2P pass per sentence
  (wordTokenCounts), not one per clause/word; prefers clause seams.
- warmLexicon() at native prepare so the 16 MB dictionaries parse while the
  model loads instead of on the first sentence.
- tokensFor() no longer falls back to letter-spelling when offline, and the
  streamed speak() path sends the same pre-phonemised tokens.
- Parallel TTS pass: tokenizer-vocab combining marks, hasOwn lexicon keys,
  signed/decimal fallback numbers, tagger fixes.
